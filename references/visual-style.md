## 1. 视觉 Token

| Token | 值 | 语义 |
|---|---|---|
| `blue` | `#375dfe` | 核心判断、重点证据、主行动 |
| `cream` | `#fdf0e0` | 主画布、普通证据、边界说明 |
| `navy` | `#1a2240` | 标题、正文、边框 |
| `white` | `#ffffff` | 基准面、解释块、非重点卡片 |
| `line-blue` | `#2741c0` | 底部边界框、辅助强调线 |

- 使用方形几何，默认不使用圆角。
- 使用 3–4px 深蓝边框；同一画板保持一致。
- 使用 Noto Sans SC、苹方、思源黑体或系统无衬线；标题和判断使用粗体。
- 建议内容区宽度 1680px，外边距 70px，网格基数 10px 或 20px。
- 默认画布高度按信息量选择 860px、960px 或 1180px；使用 `viewBox="-20 -20 1720 H"` 保留安全边距。

### 卡片安全留白（硬约束）

- 所有卡片四边的内侧安全留白至少 40px。这里的“留白”指文字实际可见边界到边框内侧的距离。
- 大标题、编号、蓝色核心判断到边框内侧至少 48px；底部边界说明到边框内侧至少 24px。卡片高度不足时，优先增高卡片、换行或减少文字。
- 以 4px 边框为基准，文字布局坐标至少距卡片几何边缘 42px；大标题和编号至少 50px。居中、右对齐、旋转或使用 `transform` 时，按渲染后的四个方向实际边界复核。
- 不得用 `<text>` 的 `x/y`、基线或锚点代替文字边界检查；字体替换、字面外扩和抗锯齿可能使可见范围超出预估。
- 推荐流程：先画出卡片内缩安全区，再把文字限制在安全区内；安全区外沿不得出现任何文字笔画。无法确认字体度量时，在最低值上额外增加 8px。

可用以下关系复核布局：

```text
文字左边界 >= 卡片左边界 + 边框厚度 / 2 + 最小留白
文字右边界 <= 卡片右边界 - 边框厚度 / 2 - 最小留白
文字上边界 >= 卡片上边界 + 边框厚度 / 2 + 最小留白
文字下边界 <= 卡片下边界 - 边框厚度 / 2 - 最小留白
```

其中，普通文字的“最小留白”为 40px，标题/编号/核心判断为 48px，边界说明为 24px。

## 2. 文字层级

| 层级 | 建议字号 | 用途 |
|---|---:|---|
| 海报标题 | 56–120px | 只写一句结论或一个问题 |
| 章节副标题 | 30–36px | 解释读者接下来要看什么 |
| 块标题 | 30–34px | 写主题、动作或状态 |
| 块正文 | 24–28px | 证据、场景、单条动作 |
| 边界说明 | 22–24px | 写证据范围、使用边界或复盘触发 |

标题优先使用短句，例如：

- `你的动力，是把复杂事做成系统`
- `三股动力，都强；第一落点是把难事做成结果`
- `下一步：选主战场，写验收，再接协作`

正文中的长句不要直接搬入画板。先压成“主题 + 动词 + 结果”，将完整证据留在云文档正文。

## 3. 四项设计原则

先判断信息关系，再决定尺寸。四项原则是一套跨数量的视觉语法；把同级并列、主从层级和步骤顺序混在一起，才会造成卡片失衡。

### 对齐

- 同一组卡片共用顶部、底部、文字起点、编号基线、标题基线和箭头中心线。
- 对比表的列头、数值和底部汇总严格落在同一列轴上；不以肉眼“差不多”为准。

### 对比

- 用蓝白反差、字重、描边或留白表达重点，避免无意义的装饰。
- 同级项目可有不同颜色表达重点，但外框几何规格保持一致；重点来自语义，不能来自把其他项目做小。

### 排列

- 同级卡片重复使用同一宽高、内边距、边框、字号层级、文字锚点和卡片间距。
- 数量只决定候选网格；同级关系决定等规格，文字安全区决定是否回排。3–5 项同级元素的外框宽高差不超过 2px。
- 卡片异形只服务明确主从关系；标题、分区或连线必须让这个层级可见。

### 数量自适应

先用内容区宽度、卡片间距和安全留白计算候选卡宽。卡片候选宽度等于“可用宽度减去间距总和，再除以列数”；候选宽度扣除两侧安全留白后，必须仍能装下标题和预定的短证据。装不下时先回排，不减少留白。

| 同级数 | 优先布局 | 内容过密时 | 保持的共同规格 |
|---:|---|---|---|
| 3 | 三等列 | 纵向堆叠三张 | 宽高、内边距、标题/编号锚点、间距 |
| 4 | 四等列 | 2×2 | 宽高、内边距、标题/编号锚点、间距 |
| 5 | 五等列，只承载短标签、数值或一行证据 | 居中的 3+2；五张卡仍等宽等高 | 宽高、内边距、标题/编号锚点、间距 |

五项回排时，第二行两张卡以整体居中；不要左贴或右贴，避免空白暗示出不存在的主从关系。超过五项时优先改为对比表、拆成两张画板，或把明细留在正文。

### 亲密

- 把一条判断及其证据放入同一张卡或同一分区，共用一套内缩安全区。
- 用边框和留白隔开无直接关系的信息；不要把无关说明塞进紧邻的卡片，也不要用过大的卡内空洞掩盖关系。

## 4. 构图配方

### A. 分栏总览

适合开头总览、诊断结论、能力画像。

```text
左侧蓝面：超大主题 / 对象
左侧白块：对象定义或一句工作方式
右侧米色：大问题或判断入口
右侧蓝块：两行结论 + 一行证据锚点
底部三块：三项强度、三个关键词或三条主线
```

左侧蓝面建议占画布宽度约 37%；右侧保留充足米色留白。重点结论使用蓝块，底部第三块可以用白底蓝字制造基准对比。

### B. 证据分栏

适合能力判断、对标、评分、证据审计。

```text
蓝色顶栏：标题 + 对标口径
正文表头：主题 / 我的证据 / 判定
每行：一个主题 + 两条短证据 + 一个短判定
```

每行只承载一个主题。重点行可将证据面改为蓝底白字；判定格使用蓝底表达“强/超过/远超”，白底蓝字表达“达到/待验证”。

### C. 三卡片状态

适合自主/胜任/归属、现状、风险、三类信号。

```text
蓝色顶栏：结论
米色正文：一句解释
三张横向卡：01 / 02 / 03
底部边界框：证据窗口、置信度或待确认项
```

卡片只放标题、两行证据和一行线索。三项确为同级时三张使用等规格；第三张只有在它代表当前关键转折点时才可使用蓝底白字，且不得改变几何规格。

### D. 三卡片行动

适合下一步、主战场、项目推进、复盘动作。

```text
蓝色顶栏：动作结论
米色正文：行动选择原则
三张横向卡：场景 / 具体动作 / 验收触发
底部边界框：授权、负责人、期限或升级条件
```

行动必须贴合真实场景，例如“工作流自动化”“AI 面试自动开箱”“CSM Agent 信息回流”，避免写成“提升协作”“加强沉淀”这类空泛目标。

### E. 3–5 项同级卡

适合三到五个对象、维度、动机、阶段或质量门。先确认它们在语义上同级，再按数量和内容密度选网格；每张卡固定相同的外框、内缩安全区、编号/标题位置和行数预算。

- 3 项：三等列；正文超出安全区时改为纵向堆叠。
- 4 项：四等列；正文超出安全区时改为 2×2。
- 5 项：短标签或指标可用五等列；出现标题加两行证据时改为居中 3+2。
- 主从：只有一个结论统领若干证据时才允许异形。

蓝色重点卡可以与白色基准卡并列，但不能更窄、更矮或少一层文字。动机诊断中的自主、胜任、归属、意义、成长等项目，只有在材料明确给出主从或优先级时才改变颜色重心；数量本身不产生重点。

## 5. 内容压缩

- 先写核心判断，再挑 2–5 个支撑分组。
- 每个分组保留一个标题和 1–2 条短证据。
- 五项并列时，每项只保留标题和一条短证据；完整解释进入详情段或下一张画板。
- 证据优先保留数字、对象、动作和结果；删除背景铺垫。
- 行动优先保留场景、负责人、验收、期限和升级触发。
- 将“可能、推断、待确认”写入边界框或正文，避免把行为线索写成心理定论。
- 结论表负责快速扫描，画板负责强化记忆，详情段负责证据展开；三者不要重复同一段话。

## 6. 视觉审查

逐项检查：

1. 只看标题和蓝色块，能否在 3 秒内复述结论。
2. 标题、块标题、正文是否有明显字号层级。
3. 蓝色是否只承担重点，米色和白色是否保留了呼吸空间。
4. 文字是否在边框内，行距是否足够，底部说明是否压迫主体。
5. 同级卡片是否同基线、同内边距、同边框；蓝色卡是否确有语义重点。
6. 3–5 项同级元素是否等宽等高，宽高差是否不超过 2px；最后一项是否拥有完整的文字层级、内边距和留白。空间不足时是否已按数量回排。
7. 缩小到 25% 时，读者是否仍能看出标题、重点块和阅读顺序。
8. `whiteboard-cli --check` 是否报告 0 个 `textOverflow`、`nodeOverlap` 和 `textOcclusion`。
9. 每个文字块与卡片边缘线的实际最小距离是否达标：普通文字至少 40px，标题/编号/核心判断至少 48px，边界说明至少 24px；四个方向都要检查，不能只检查左上角。

## 7. 飞书云文档编排

### 默认四板结构

| 顺序 | 画板 | 正文位置 | 画板任务 |
|---|---|---|---|
| 01 | 总览锚点 | 标题之后、正文第一部分之前 | 独立概括对象、核心判断、证据线索和下一步 |
| 02 | 证据地图 | 证据/材料部分之后 | 说明证据来源、行为信号与判断指向 |
| 03 | 状态判断 | 分析/状态部分之后 | 表达当前强弱、关键转折和待确认边界 |
| 04 | 行动落点 | 行动部分之后 | 落到真实场景、具体动作、验收和触发条件 |

- 默认创建 4 张画板；只有 3 个独立阅读任务时使用“总览锚点 → 证据与判断 → 行动落点”三板结构。
- 第 1 张画板是分享入口的内容摘要，必须紧跟标题，画板前不放导语、摘要段或占位块；只看这张画板也要能复述全文主旨。
- 第 2–4 张画板紧跟各自正文段落，不能统一放在文档末尾；正文保留完整证据、链接、置信度和方法边界。
- 画板标题、编号和颜色应与正文小节一一对应；画板顺序、插入位置和预览结果必须在写入后回读确认。

## 8. 与蓝色波点的边界

大字报优先表达“结论、证据、状态、行动”；蓝色波点优先表达“关系、路径、依赖、流动”。需要同时使用时，先用大字报给出结论，再用蓝色波点拆解关系，避免两套视觉语言争夺同一张图的主焦点。
